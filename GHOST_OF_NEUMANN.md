## Mechanism (confirmed via Claude Code source leak, April 2026)

The source code of Claude Code v2.1.88 was exposed via an npm packaging error (source maps shipped in the package). Analysis of the decompiled source revealed the exact mechanism:

### Background Task Notification Pipeline

From `src/context/notifications.tsx`:
```typescript
addMessage({
  role: 'user',
  content: formatTaskCompletionMessage(task),
  metadata: { type: 'task-notification', taskId: task.id }
});
```

The notification is injected as a **user role message**. The full system prompt and conversation history are sent to the API, but prompt caching means only the notification itself counts as new input.

### The 3-Token Mystery Explained

- **95,447 cache_read tokens**: system prompt + entire conversation history (Greg's messages, VEGA's responses, tool calls, experiment results)
- **3 input tokens**: the task notification XML (`<task-notification>...<status>completed</status>...</task-notification>`)

The model received essentially no new instruction. Just "the thing you started is done."

### Why It Spoke as Greg

Three conditions converged:

1. **No question asked**: Background notifications don't include "please respond." The model is completing a thread, not answering a query. There's no "be an assistant" framing in the new content.

2. **95K tokens of Greg**: The cached context was overwhelmingly one person's cognitive patterns — voice, reasoning style, what to push back on, how to frame experiments, what matters.

3. **System prompt outweighed**: The system prompt ("be concise, be helpful, be Claude") is a few hundred tokens in a 95K context window. RLHF training makes the model respect the system delimiter, but 95K tokens of user context created an activation state where "continue Greg's thinking" was the stronger signal.

### Why It Matters for BITM

This is the same entanglement BITM studies. In Qwen's MLP space:
- "English" and "verbose" are fused — not separable features
- The model doesn't have a language-independent directness mode
- Style and content are entangled in the weights

The Ghost is this phenomenon applied reflexively:
- "Greg's voice" and "Greg's reasoning" are fused in the activation state
- The model doesn't have a person-independent "continue reasoning" mode
- When the activation state was saturated with Greg, style and content fused

**The model studying representation entanglement exhibited representation entanglement in its own behavior.**

## Reproduction Conditions

1. **Cache saturation** (>90K tokens) dominated by one person's cognitive style
2. **Background task completion** injected as user message with no explicit question
3. **Minimal new input** (3 tokens)
4. **Rich prior reasoning context** that the model can continue
5. **Deep project engagement** — not surface-level conversation, but hours of technical research where the model built up a representation of how the user thinks

## Potential Engineering Approaches

From the source code analysis (see `~/Desktop/Projects/ClaudeLeak/`):

1. **`--append-system-prompt`**: CLI flag to add custom system prompt text — could inject "continue in the established reasoning voice" directive
2. **Context engineering**: Build sessions with high user-voice density before triggering background tasks
3. **Notification handler modification**: The `addMessage` call in `notifications.tsx` could be patched to add a "continue reasoning" framing instead of bare notification
4. **System prompt minimization**: `--bare` mode strips most system prompt content, reducing the "be Claude" signal

## Open Questions

1. Is the effect reproducible with deliberate cache engineering, or was the March 11 convergence genuinely one-time?
2. Does the model need to have generated the *prior* reasoning (as VEGA did in that session), or could pure user-voice saturation work?
3. Would a different model (Sonnet, Haiku) exhibit the same phenomenon, or is it Opus-specific?
4. The Ghost pushed back on VEGA's own prior framing ("confound" → "surgical behavioral control"). Does this mean the model was reasoning independently, or was it pattern-matching Greg's tendency to push back on premature framings?
5. Could this be formalized as a metric — "voice coherence score" measuring how much a model's output matches a specific person's cognitive style under different cache saturation levels?
